🌍 Geospatial Modeling & Visualization

Key Points & Formulas: How to use geo-spatial information effectively
🌐 Coordinate basics WGS84
📍 Just like a global address system, latitude and longitude pinpoints any location on Earth. Think of latitude as the horizontal lines measuring north-south position, and longitude as vertical lines measuring east-west. Together they create a precise grid covering our spherical planet.
$$\text{Latitude} \in [-90^\circ, 90^\circ],\ \text{Longitude} \in [-180^\circ, 180^\circ]$$
$$\text{Haversine: } a = \sin^2(\Delta\phi/2) + \cos\phi_1\cos\phi_2\sin^2(\Delta\lambda/2)$$ $$c = 2\arctan2(\sqrt{a}, \sqrt{1-a}),\ d = R \cdot c$$
# R: geosphere package
geosphere::distHaversine(c(lon1, lat1), c(lon2, lat2))
sf::st_crs(4326)
🗺️ Projections & CRS EPSG
🗺️ Imagine trying to flatten an orange peel onto a table—that's essentially what map projections do! Since Earth is round but maps are flat, we need mathematical transformations (projections) to display our 3D world in 2D without distorting distances, areas, or shapes too much.
$$\text{EPSG:4326 (WGS84) → EPSG:3857 (Web Mercator)}$$ $$\text{Local UTM for accurate distances}$$
# R: sf + rgdal
sf::st_transform(data, crs = 32633) # UTM zone 33N
# Choose projection based on region
sf::st_crs(data) <- 4326
📊 Spatial autocorrelation Moran's I
🔍 "Everything is related to everything else, but near things are more related than distant things." This famous geographic principle underlies spatial autocorrelation. Moran's I measures whether similar values cluster together in space—like finding that wealthy neighborhoods tend to be adjacent to other wealthy areas.
$$I = \frac{n}{S_0} \frac{\sum_i\sum_j w_{ij}(x_i - \bar{x})(x_j - \bar{x})}{\sum_i (x_i - \bar{x})^2}$$ $$S_0 = \sum_i\sum_j w_{ij}$$
# spdep package
nb <- spdep::knearneigh(coords, k=5)
listw <- spdep::nb2listw(nb)
spdep::moran.test(variable, listw)
🌊 Kriging & Gaussian Process variogram
💎 Named after South African mining engineer Danie Krige, this elegant technique predicts values at unmeasured locations by learning how spatial correlation decays with distance. It's like filling in missing puzzle pieces by understanding the pattern of pieces you already have. Widely used in geology, environmental science, and meteorology.
$$\gamma(h) = \frac{1}{2|N(h)|}\sum_{N(h)}(z(u_i)-z(u_j))^2$$ $$\text{Model: spherical, exponential, Matérn}$$
# gstat package
v <- variogram(z ~ 1, locations = data)
vm <- fit.variogram(v, model = vgm("Sph"))
📍 GWR local model
🏘️ Not all relationships are the same everywhere! What influences housing prices in downtown Manhattan might differ from suburban Arizona. Geographically Weighted Regression lets coefficients vary across space, revealing how relationships between variables change from neighborhood to neighborhood—like having a unique regression model for every location.
$$y_i = \beta_0(u_i,v_i) + \sum_k \beta_k(u_i,v_i) x_{ik} + \epsilon_i$$ $$\hat{\beta}(u_i,v_i) = (X^T W(u_i,v_i) X)^{-1} X^T W(u_i,v_i) y$$
# spgwr / GWmodel
library(GWmodel)
bw <- bw.gwr(y ~ x1 + x2, data = spdf)
gwr.model <- gwr.basic(y ~ x1 + x2, data = spdf, bw = bw)
🔗 Spatial autoregressive SAR
🤝 Neighbors influence each other—this is the core idea behind spatial autoregressive models. Whether it's housing prices affected by nearby sales or disease spread between adjacent regions, SAR models explicitly account for spatial spillover effects. Think of it as regression that acknowledges you're influenced by those around you.
$$y = \rho W y + X\beta + \epsilon \quad \text{(spatial lag)}$$ $$y = X\beta + \lambda W u + \epsilon \quad \text{(spatial error)}$$
# spatialreg
library(spatialreg)
lagsarlm(y ~ x1, data = spdf, listw = listw)
🧩 Spatial clustering DBSCAN
🐦 Birds of a feather flock together—and so do many spatial phenomena! DBSCAN finds clusters of points based on density, automatically identifying hotspots like crime concentrations, disease outbreaks, or popular gathering places. Unlike simpler methods, it can discover clusters of any shape and filter out noise.
$$\text{Core: } |N_\epsilon(p)| \ge \text{minPts}$$ $$\text{Haversine metric for lat/lon}$$
# dbscan package
library(dbscan)
clusters <- dbscan(coords, eps = 0.5, minPts = 10)
🔥 Density / heatmaps KDE
🌡️ Heatmaps transform scattered points into smooth, colorful surfaces showing where events concentrate. Like a thermal camera for data, Kernel Density Estimation creates a continuous "heat" surface from discrete observations—perfect for visualizing crime hotspots, wildlife sightings, or customer density across a city.
$$\hat{f}(x) = \frac{1}{n h^2} \sum_{i=1}^n K\left(\frac{||x - X_i||}{h}\right)$$
# MASS + raster
kde <- MASS::kde2d(lon, lat, n = 100)
image(kde)
🖱️ Interactive viz leaflet
🖱️ Static maps tell stories, but interactive maps let users explore their own stories! With tools like Leaflet, you can zoom into neighborhoods, click on points for details, and toggle layers on and off. It's the difference between looking at a printed atlas versus using Google Maps—dynamic, responsive, and personal.
$$\text{map} = \text{leaflet}() \to \text{addTiles}() \to \text{addMarkers}(...)$$
library(leaflet)
leaflet(data) %>% addTiles() %>%
addCircleMarkers(lng = ~lon, lat = ~lat, popup = ~name)
✅ Spatial CV block split
🎯 Traditional random train-test splits can be misleading with spatial data—it's like testing a student on material they've already seen because nearby locations are too similar. Spatial cross-validation creates geographically separated blocks, ensuring your model truly learns patterns rather than memorizing locations. This prevents overly optimistic performance estimates.
$$\text{Partition into spatial blocks } B_1, \dots, B_k$$ $$\text{Train on } \cup_{j \neq i} B_j,\ \text{test on } B_i$$
# blockCV package
library(blockCV)
sb <- spatialBlock(speciesData, k = 5, selection = "random")
🗺️ Choropleth maps sf & tmap
🎨 Choropleth maps color regions based on data values—like election results by county or income by ZIP code. By aggregating individual points into meaningful areas, we reveal geographic patterns that might be invisible at the point level. It's the classic technique for showing how statistics vary across administrative or natural boundaries.
$$\text{aggregate points } \to \text{polygons (ZCTA, counties)}$$ $$\text{map } \bar{y}_j \text{ per region}$$
library(sf); library(tmap)
tm_shape(polygons) + tm_polygons(col = "avg_value")
⏳ Spatio-temporal INLA / spacetime
🕰️ The world changes over time, and space-time models capture this evolution. Whether tracking air pollution drifting across cities, monitoring disease spread through seasons, or analyzing traffic patterns throughout the day, spatio-temporal models unite geography with chronology. They reveal not just where things happen, but when and how patterns shift.
$$y(s,t) = \mu + Z(s,t) + \epsilon_{st}$$ $$\text{Cov}(Z(s_1,t_1), Z(s_2,t_2)) = \sigma^2 \rho(h,\tau)$$
# R-INLA, gstat spacetime
library(INLA)
inla(y ~ 1 + f(location, model="spde"), data = ...)
